Section 2 — The landing page and multi-project work: what exists

I checked all the systems, GitHub and Google Drive, and the work you remember does exist. It is in the VisionWeaver repository, in a research note dated September 30, called v8: projects, onboarding, and execute. It records your ask from that day, in your words: more than one project, before the editing work. What was built from it is real. There is a Projects page with one card per project, showing its type, its stage progress, the stage it is on now, the next step, and how many decisions are waiting. There is a project menu at the top that switches the active project, saved per person. There are six project types, episode, social media piece, kids video or book, podcast, document or book, and something else, and each type carries its own stage template with the two gates built in, in every project. Onboarding even offers a new project as one of its starting paths. I verified the code in the site itself: projects are created by a real function, stored in the database when one is connected, and kept in the browser when one is not. Crossroads Episode 1 is registered as the built-in project, and its stages open the original pipeline pages. Now the gaps. The site as it currently stands does not open on that Projects page. It opens on the Command Board, so the landing page you asked for exists but is not the front door. Only Crossroads is registered. This Is Your Life, The Arc, and the psychology series all exist in the repositories and in Drive, but none of them is a project inside the Studio yet. And a new project today gets a generic stage board, not the full pipeline pages Crossroads has. In Drive, I found no landing page work at all. The Drive pieces, the system document, the replication prompt, and the dashboards from July, are all from the earlier, single-project era.
