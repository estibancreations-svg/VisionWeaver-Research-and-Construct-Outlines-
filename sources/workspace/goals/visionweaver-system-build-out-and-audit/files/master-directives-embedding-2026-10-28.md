### Where it goes in the Master — not as a loose document

It does NOT go as a project in Programs & Projects, and it does NOT go as an asset in Media Library. It goes as the system layer, in five places, with one master copy:

1. **Settings → Directives — master copy, versioned.** One source of truth. Changing a directive here changes the rule everywhere else. No duplicate copies in other pages.
2. **AI Co-Pilot → orchestration rules.** THELMA, research, content, video, compliance, CMGIO, and quality agents must follow the directives, propose-only, human approval. This is the same injection Director Studio OS did: the operating map is injected into the assistant context.
3. **THELMA drawer → context.** THELMA reasons across Avatar State, World State, commercial work, finance, memory, infrastructure, and quality using the directives, without pretending unverified integrations are live.
4. **Pipeline stages → gates with required returns.** Each directive becomes a check that blocks the next stage until its required return is present. Examples: D4 Script spine — Create & Produce intake cannot queue without a locked script; D5 Board system — Avatar Engineering / Worlds cannot render without a board check; D10 Funding gate — no paid run while funding is on hold; D12 Approval gates — Publish cannot fire without the word APPROVED; D9 Delivery format — no audio ships on a duration check alone, content must be checked against its script.
5. **Assets & Knowledge → Standards Library (reference copy only) + Resources → Workflows / Production Guides (human-readable copy only).** These are read-only mirrors of the Settings master copy, so a human can read the method without editing the live rule by accident.

### How it is embedded — as data, not as a PDF alone

The PDF stays as the human-readable record and as the archive reference. In the Master itself, each directive is stored as a rule record:

- Statement: what the rule is.
- How to create it: the creation method, in steps.
- Required return: the exact artifact that proves the step was done (script, board, cost statement, APPROVED word, receipt, etc.).
- Gate: what is blocked until that return is present, and who can release it (you, by pick / APPROVED).
- Stage: Create & Produce, Scene & Production, Post Production, Quality & Audit, Distribution & Growth, or All stages.
- Check type: human pick, or automated check (for example, cost stated before run, file in quarantine, sample label present).

A story cannot move past a gate in Demo or Blank without that return, in either mode. In Blank, directives are present (system accounted for); only demo data is empty. In Demo, directives are present and the proof stories (First in Consciousness, Crossroads) run through them.
