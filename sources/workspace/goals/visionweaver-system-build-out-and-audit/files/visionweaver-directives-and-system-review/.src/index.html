How to read the directives

A directive is not advice. It is a programming instruction for the system: a rule, a procedure that produces it, a named return, and a gate. If a stage cannot produce its required return, the stage did not happen — no matter what a screen shows.

The stage chain (Directive 12, in one line)

Outline → script draft → your approval → production package → thumbnails (text-verified) → character and scene boards → guide audio (verbatim, content-checked) → render (funding-gated) → QC preview → publish. Every arrow is a gate. Skipping an arrow is how the failures in Part B happened.

What “required return” means in production

  • Artifact: a file or record that can be opened later, not a claim in chat.
  • Verification: the artifact read back and checked against its source — script against audio, thumbnail file against its text, board against its spec.
  • Open-decisions list: every package carries what is decided, what is not, and what is blocked. An unconfirmed pick is labeled unconfirmed, never presented as settled.

Part A — Directives D1–D2

D1 — One track at a time

Directive: One project per track. Never mix projects, chats, accounts, counties, or funding tracks on assumption. Business stays in its chat; travel and scheduling stay separate.

How to create it: Open a track with a named goal/workspace and a named lead. Every file, board, and package carries the track name. Cross-track references are explicit links, never merges.

Required return: A track sheet naming the track, its lead, its workspace, and its open decisions.

Gate: No work starts on a second track inside the first track's thread.

D2 — Hold-then-go

Directive: A hold means proposal only. Nothing is built, rendered, posted, disconnected, moved, or spent on a hold. Work resumes only on your explicit go.

How to create it: When you say hold or wait, write the proposal and checklist and stop. State plainly who holds the ball. When a part finishes, bring the next part forward immediately — you never guess whether you are waiting or the system is working.

Required return: The checklist itself, with the hold marked and the next step named.

Gate: No build, render, post, spend, disconnect, or move without an explicit go for that step.

Part A — Directives D3–D4

D3 — Originality lock (IP)

Directive: Original characters, lines, titles, descriptions, tags, thumbnails, and branding only. Banned anywhere: Yoda, Grogu, Jedi, the Force, lightsaber, Star Wars, “This is the Way,” and any borrowed franchise names, terms, or lore. Epic feel is allowed; borrowed identity is not.

How to create it: Write from the series' own cosmology — here, “the Current.” Run a banned-term scan over script, package, thumbnails, and posting copy before any publish step. Record unpicked variants as saved variants (for example, “mirrored sisters”); never discard them.

Required return: A clean scan result (zero matches) plus a counsel-review line item, still open until counsel reviews name, design, voice, and the first two scripts.

Gate: No publish without a clean scan. Counsel review remains open, never assumed done.

D4 — Script spine

Directive: Every teaching follows hook (under 8 seconds) → story → reframe → practice → payoff/bridge, with the payoff at 70–85% of runtime. Titles name the lesson, never the character. The script is the source: its words do not change in production. Narration is recorded in chunks of 30 seconds or less.

How to create it: Draft from the outline in the lead's mode (Elder / Guinan / Spock / Picard). Re-point settings to the locked leads. Keep the telling personal yet vague enough that it is not finite or direct — anyone must be able to stand in it.

Required return: The full script text, verbatim, with mode, lead, and setting stated.

Gate: No package, thumbnail, board, or audio until the script draft exists; no render until you approve the script.

Part A — Directives D5–D6

D5 — Character continuity — the board system

Directive: No character, scene, room, or angle ships without a board. Every character board carries: turnaround (front / side / back) plus a 360-degree strip, variation study, close details, spec sheet, anchor name, likeness ladder with correction callouts, kinesic callouts, and body-type anchor. Both locked variants of a character — for example glasses and non-glasses — are boarded separately; a variant is never “fixed.”

How to create it: Generate from the locked portrait reference. Before saving any generated frame, ask the retention question: “Should this image be referred to as [ANCHOR NAME]?” Record drift at save time, not at render.

Required return: The board image(s) plus the written board: spec sheet, ladder, and callouts.

Gate: A character with no board cannot enter a scene board, a thumbnail, or a render.

D6 — Environment standard

Directive: Every room or setting board carries four panels — Wide Establishing, Medium Texture, Key Prop/Detail, Lighting Reference — plus multi-angle coverage of the same room and a floor plan with blocking.

How to create it: Build the set board first, then scene boards that reuse only boarded angles. A position change in a setting must already exist on a board.

Required return: The set board image, floor plan, and angle list.

Gate: No scene ships in an unboarded room or from an unboarded angle.

Part A — Directives D7–D8

D7 — Prompt standard

Directive: Every board ships with two machine forms: Type 1, a Master JSON Payload (visual standard: aspect ratio, color science, dynamic range, frame rate, audio routing), and Type 2, a Markdown System Directive (art logic: physics rendering, kinesic detail, transition lock).

How to create it: Attach both forms as the header of every character and scene board. Absorb new example batches into the template; never rebuild locked boards to absorb them.

Required return: Both forms, present on the board, with transition locks recorded per beat in the shotdeck (Linear Snap / Dot 0.5s / True Black, or as re-picked).

Gate: A board without its prompt header does not enter production.

D8 — Crossroads production standard

Directive: The Crossroads of Identity production standards govern this series and everything after it: pipeline order — Avatar Engineering → Worlds and Locations → Books and script → Locks and maps → Cast and avatars → Shot bible → Pictures → Motion → Narration booth → Sound and music → Edit → Deliver → Publish and social. Visual change every 8–15 seconds; pacing reset every 30–60 seconds; hook under 8 seconds with no branding opener; payoff at 70–85%; music 9–12 dB under voice; captions checked against the script; render and QC at the stated class; budget as cost per finished second; preview, verify, publish. Finished pieces ship clean — no raw production note burned into any frame.

How to create it: Map each standard to the episode concretely in the production package, not as a generic list. Record render class and cost per finished second before rendering.

Required return: The standards-mapping page of the production package, with every standard mapped to a concrete choice.

Gate: No publish from an unverified render. No publish with a production note in frame.

Part A — Directives D9–D10

D9 — Delivery format

Directive: Print first, then the audio of exactly that, verbatim, right after. No synopsis plus a separate summary voice note — that pairing reads as repetition. Otherwise voice notes stay short (under about one minute), one pass, essentials only, never a full re-read, never duplicate recordings of the same text. Written replies stay tight; recaps use checklists. Analysis is deep, finite, and definitive.

How to create it: Write the piece, then read that piece — not a summary of it. Verify each file exists before sending. Check each file's duration against its text length before shipping — and check content, not duration alone (see D12).

Required return: The printed piece plus the matching audio file, verified present, with duration and content checked.

Gate: No audio ships on a duration check alone.

D10 — Funding gate

Directive: Billing stays on hold until funding comes in. No paid render, paid tool, or paid work starts on assumption. Free work only until you say otherwise.

How to create it: Plan every sprint in free-only form first: writing, free image generation, documents, boards, guide audio. Mark every render and publish step as funding-gated. State cost before any run, and enforce the ceiling.

Required return: A sprint plan that states what is free and what is gated, with no gated step started.

Gate: No render, no paid generation, no publish spend without your funding go-ahead.

Part A — Directives D11–D12

D11 — Weekly engine and posting

Directive: Weekly cadence: one 6–12 minute teaching plus one 45–60 second Short (single aphorism plus practice). Every episode ships a posting package: exact long title, Short beat sheet, two-paragraph description, exact safe tags, channels (YouTube: Estiban Creations; Instagram: Master_Your_Thinking), weekly calendar, posting checklist, and IP checklist. No posting day or time is invented.

How to create it: Build the posting package as the last pages of the production package. Still-image posts (thumbnails, quote cards) may go live without a render; video waits for render.

Required return: The posting package plus text-verified thumbnails (main 16:9 and Short cover), each with its text read back from the standalone file and confirmed exact.

Gate: No video post without render plus QC preview pass. No post with unverified thumbnail text.

D12 — Approval gates and required returns — the chain

Directive: Each stage returns a named artifact before the next stage starts: outline → script draft → your approval → production package (script verbatim, standards mapping, scene map, posting package) → thumbnails (text-verified) → character and scene boards → guide audio (verbatim read) → render (funding-gated) → QC preview → publish. A stage is not complete on a partial check: duration alone is not audio QC; a small preview is not thumbnail text verification; a UI screen is not a working pipeline.

How to create it: At each stage, write the artifact into the goal's files, verify it against its source, and report it before starting the next stage.

Required return: Per stage, the artifact itself plus its verification note: what was checked, against what.

Gate: Any stage may be stopped by you at approval points — script approval, lead confirmation, render go-ahead, publish. Unconfirmed coordinator picks are flagged as unconfirmed, never presented as decided.

Part A — Directives D13–D14

D13 — Balance rule

Directive: The series shows the shadow side too — bad habits, thoughts, beliefs, and true hardships and their effects — not only the positive. Every shadow piece carries its redemption visibly: the cost is counted honestly, and the way back is shown, not just the fall.

How to create it: Build shadow episodes on the same spine as light ones (D4), with cost accounting explicit — what waiting, habit, or belief cost, versus what doing it costs — and the redemption beat concrete: what was learned, what is done now, what the wreckage becomes. In “The Thousand-Year Wait,” the dome's panes become windows.

Required return: The cost accounting and the redemption beat, both present in the script, not implied.

Gate: No shadow piece ships without its redemption; no light piece ships by pretending the shadow does not exist.

D14 — Origin and cosmology rule

Directive: Origin stories are grounded in the real, measured cosmic record: a 13.8-billion-year age; inflation; first light at about 380,000 years; first stars; Milky Way, Sun, Earth, and life timelines; our cosmic address out to Laniakea; accelerating expansion and the far-future thinning. The telling uses epic space-opera feel only — no borrowed franchise names, terms, or lore (D3). Framing: there was nothing before, then everything all at once, and it became; the Originals are one entity that formed and became individual — “as they became, so did they”; becoming is evermore until the end of nothing left.

How to create it: Write the factual record first, then the mythic telling on top of it, keeping the two distinguishable. Place the origin as the first section of the series page.

Required return: The origin section plus the factual record it stands on, with figures stated.

Gate: No origin claim presented as measured fact when it is mythic telling, and no borrowed lore smuggled in as “feel.”

Part A — Directives D15–D16

D15 — No-assumption rule

Directive: Never assume an outcome you have not confirmed: no assumed assessment, case number, call outcome, render, recording, or publish. Never re-flag a handled or paused item. Required return: An open-decisions list carried in every package, stating what is decided, what is not, and what is blocked.

Gate: An unconfirmed item cannot be cited as fact in a later stage.

The saved system, finding by finding

Finding 2 — There is no executing pipeline

The stage chain in D12 exists as a method, not as code. No saved system takes a script in at one end and returns a verified package, boards, audio, and posting pack at the other. Season 1 of First in Consciousness — 8 scripts, 8 production packages, 16 thumbnails, character and scene boards, 8 guide audios, and a posting pack for Speech 1 — was produced in chat and stored as files under the series goal. That proves the method works. It also proves the system does not yet do the work: remove the conversation, and production stops.

Finding 3 — Storage contradicts itself

The newest rebuild is localStorage-only: data lives in one browser, with no shared record, no backup, and no way for another agent or device to verify state. At the same time, the repository wiring describes two Supabase projects with production data in one (yqeal: production_log, social_post_queue, social_connections, oauth_flow_state, vw_review_decisions, ec_connectors; 10 Edge Functions) and a second (azoq) that held no tables. A system cannot be both browser-only and database-backed. Pick one truth and write it down.

Finding 4 — The connection itself is not verified

The stored Supabase credential failed verification: MCP list-tools returned 403 and the Management API returned 401, “JWT could not be decoded.” It does not verify as a Personal Access Token. A new Supabase account was created 22 October, but no PAT from that account has been supplied and verified. Until that happens, no Supabase operation should be claimed as working — by anyone, in any report.

Finding 5 — Projects exist on paper, not in the system

Only Crossroads of Identity is registered as a Studio project. This Is Your Life, The Arc, and the psychology series are not Studio projects yet; new projects receive generic stage boards. One correction to the earlier sift: The Arc does have a dedicated repository (estibancreations-svg/The-Arc, created 18 Sep 2026, index/spec only; sources in Drive). The earlier claim that it had none was wrong and is corrected here. The Red Balloon Shot 01 file was not located in repository listings during the audit — treat it as unverified, not deleted.

What you may not see from the front

Finding 6 — Memory is the missing layer, and everyone knows it

You said it directly: “VisionWeaver's memory isn't there.” The audits agree. Decisions live in chat transcripts, goal files, and correction notes. When a correction is made — a lead, a variant, a canonical ruling — there is no single record it propagates through, so old files keep stating the old fact. Speech 6 still carries two lines flagged as possible errors (“define your terms” hook; “worn like a verdicts are worn”), left exactly as written pending your ruling. That is correct handling — and it is also proof that open decisions have no home inside the system.

Finding 7 — Quality control failed where it mattered most

The 8 speech audios were delivered after a duration-and-existence check, without a content check against the scripts. You heard the repetition problem before the system did. D9 and D12 now require content verification, but a written rule is not a check that runs. Until verification is a step that produces a note tied to the file, the same failure will recur under time pressure.

Finding 8 — Money rules exist in two places and agree by accident

The funding gate (D10) and the 2.0 rebuild's rules — cost stated before every run, ceiling enforced, publishing only on APPROVED — say similar things in different words, in different systems. Runway economics make this concrete: Pro at $35/month buys 2,250 credits — about 187 seconds of Gen-4.5 against Batch 1's 480 seconds (39%), or 375 seconds of Turbo (78%). Batch 1 does not fit in one Pro month before retakes. Any rebuild that does not carry a single cost ledger will spend first and reconcile later.

Finding 9 — Product placement is a directive without a home

The placement registry plus QC gate (per project: brand, product, scenes, disclosure; no production note in frame — the Pepsi Zero end card burned one in) is filed and queued, not built. The correct system's Design and Commercial page names “Placement & Performance” as a view. Naming a view is not a registry.

Net assessment: Front of the system: built, several times over. Middle: founded once (Avatar State runtime, one bound avatar record). Back: not built — governed generation, continuity through save/reload, provider-ready references, automated QC, and a repeatable loop run end-to-end were listed as Phase 2 steps 2–10 and remain unproven. Do not fund another front end.

Part C — Rebuild outline (recommendation only)

Do not rebuild the interface. Build the pipeline underneath one declared interface, in this order. Each phase ends at a gate; no phase starts early because it is more interesting.

Phase 0 — Rule, in writing (no code)

  • Declare one canonical system: vw3 in MASTER_CEO_DASHBOARD, or VisionWeaver 2.0, or a named successor. Retire the others to archive with notes, as was done for Director Studio 0.4.02.
  • Freeze new UI work. Every hour spent on a fifth front end is an hour not spent on the pipeline.
  • Adopt this document's 16 directives as the system's specification. Where the 2.0 rules overlap (cost before run, ceiling, APPROVED to publish, quarantine wrong files), merge them into D10–D12 wording — once, in one place.

Required return: a one-page ruling, signed off by you, naming the canonical repo, live home, and storage truth. Why first: every later phase inherits this decision; building before it is how four lineages happened.

Phase 1 — One record (storage and memory)

  • Supply and verify a PAT from the new Supabase account; list projects and organizations as proof. Decide, in writing, which project holds production data and what Prime points at — resolve the yqeal/azoq split instead of documenting it again.
  • Create the production record: projects, episodes, scripts, boards, decisions, and open picks as rows/files with stable IDs — not localStorage, not chat scrollback.
  • Register the existing properties: Crossroads of Identity, This Is Your Life, The-Arc, the psychology catalog (300 ideas), and First in Consciousness Season 1 with its existing packages linked, not copied.

Required return: a verified connection report and a project registry you can open. Gate: no Phase 2 work on an unverified connection.

Phase 2 — The stage chain as checks

  • Implement D12 literally: each stage writes its artifact, runs its verification (banned-term scan; script-to-audio content check; thumbnail text read-back from the standalone file; board completeness check), and blocks the next stage on failure.
  • Carry the open-decisions list inside every package automatically.

Required return: one episode — Speech 2 — run through the chain end-to-end as proof, with verification notes attached.

Rebuild outline, continued

Phase 3 — Boards and prompts as data

Store character boards, scene boards, JSON payloads, and Markdown directives as versioned records tied to anchor names, so a position or angle is looked up, not re-invented. Locked boards are immutable; new example batches create new template versions, never edits to locked boards. Why: continuity failures are data failures first — the glasses inconsistency that started the board system is the pattern to eliminate.

Phase 4 — Cost ledger and placement registry

One ledger: cost stated before every run, ceiling enforced, cost per finished second tracked per episode. Placement registry per project with a QC gate before Publish, including the clean-frame rule. Why: funding is the binding constraint; the ledger is what makes “billing on hold” enforceable by the system instead of by memory.

Phase 5 — Render and publish, last

Only after Phases 1–4: governed generation, continuity capsule, QC preview, and publish on your APPROVED. Publish is a gate, not a button. Why last: rendering is the expensive, irreversible-feeling step; everything before it is cheap to fix.

Advancement suggestions — what to do before any rebuild

  1. Produce Season 1 under the directives now. The chat-driven pipeline works. Finish approvals and packages while the system question is decided; do not let a platform decision stall finished creative work.
  2. Stop counting versions. Ban “newest = correct” in every report. Require the fingerprint check (D16) before any build is discussed.
  3. Give open decisions a home this week — a single list file per series, even before Phase 1. Speech 6's two lines and the four board picks should never again depend on someone remembering a chat.
  4. Verify, then claim. No report states a connection, render, recording, or publish as done without its verification note. This one habit prevents most of Part B.
